# Керн — браузерная 3D-игра

Экшен от третьего лица по сценарию из `docs/scenario.md`. Курьер Лёва из Тулы «доигрывает» оборванные записи прошлого, которые Земля проигрывает в настоящем. Перед любой работой над сюжетом, диалогами, боссами или механиками перечитай нужный раздел сценария: он главный источник правды.

Игра запускается в Google Chrome по ссылке, без установки. Публикуется на GitHub Pages.

## Текущая цель

**Вертикальный срез: пролог «Ваш заказ у двери».** Это примерно 15 минут игры. Остальные главы не начинать, пока пролог не играбелен от начала до конца и не одобрен владельцем проекта. Код при этом сразу писать так, чтобы главы 1–6 добавлялись как новые данные и сцены, а не переписыванием систем.

## Стек

- **Three.js** для рендера (WebGL2), **TypeScript** в strict-режиме, **Vite** для сборки.
- **Rapier** (`@dimforge/rapier3d-compat`) для физики и коллизий.
- **Web Audio API** для звука. Звук и музыка генерируются кодом, пока нет готовых файлов.
- Без UI-фреймворков: HUD и меню на обычном HTML/CSS поверх canvas.
- Тесты логики на **Vitest**: шкалы, концовки, сохранения, ИИ-состояния. Рендер не тестируем.
- Node 20+, менеджер пакетов npm.

## Публикация

- Репозиторий публичный, ветка `main`.
- Workflow `.github/workflows/deploy.yml` собирает проект (`npm ci && npm run build`) и публикует `dist/` на GitHub Pages через `actions/deploy-pages`.
- В `vite.config.ts` указать `base: '/<имя-репозитория>/'`, иначе ассеты не найдутся на Pages.
- Каждый пуш в `main` обновляет игру по адресу `https://<логин>.github.io/<имя-репозитория>/`.
- Перед пушем: `npm run build` и `npm test` должны проходить без ошибок.

## Структура

```
src/
  main.ts              точка входа, загрузка, игровой цикл
  core/                цикл, ввод, события, сохранения, загрузчик сцен
  player/              контроллер Лёвы, камера, захват цели, самокат
  combat/              удары, блок/парирование, рывок, хитбоксы, урон
  systems/             заедание, громкость, хвосты, шкала Аккорда, выборы
  enemies/             базовый Отпечаток, люди-Реставраторы
  bosses/              по файлу на босса (druzhinnik.ts и т. д.)
  dialogue/            движок диалогов и выборов
  audio/               синтез звука, адаптивная музыка, эффект заедания
  ui/                  HUD, меню, пуши доставки, оценка клиента
  levels/              по папке на главу (prologue/)
  data/                тексты диалогов, параметры боссов, баланс (JSON/TS)

public/                модели, текстуры, звуки, когда появятся
```

## Правила кода

- Игровая логика отделена от рендера: системы работают с данными, Three.js только отображает. Тогда логику можно тестировать без браузера.
- Фиксированный шаг логики 60 Гц, рендер с интерполяцией.
- Баланс (урон, тайминги, окна парирования, скорость роста шкал) только в `src/data/`, не хардкодить в логике.
- Все тексты игры на русском и лежат в `src/data/`, не в коде.
- Общение систем через шину событий (`hit`, `parry`, `phaseBroken`, `lastNote`, `choiceMade`), а не прямыми вызовами между модулями.
- Цель по производительности: стабильные 60 FPS на среднем ноутбуке в Chrome. Low-poly, мало источников света, инстансинг для повторяющихся объектов.
- Объём первой загрузки пролога до 30 МБ. Главы грузятся отдельно.

## Управление

Клавиатура и мышь, позже геймпад через Gamepad API.

| Действие | Клавиши |
|---|---|
| Движение | WASD |
| Камера | мышь (pointer lock) |
| Удар | ЛКМ |
| Блок / парирование | ПКМ (удерживать / нажать в такт) |
| Рывок | Shift |
| Захват цели | Q или колесо мыши |
| Суперудар «Аккорд» | E |
| Ультраудар «Последняя нота» | R |
| Датчик Ники «Тишина» | F |
| Пауза | Esc |

## Механики: как их реализовать

Полное описание и сюжетное обоснование в `docs/scenario.md`, раздел «Бой и игровые механики». Здесь только то, что нужно для кода.

**Базовый бой.** Серия из трёх ударов с окнами для продолжения. Блок снижает урон. Нажатие блока в окне перед ударом врага — парирование: урона нет, враг открыт, шкала Аккорда растёт. Рывок даёт короткие i-frames. Против людей у Лёвы другой набор действий: термосумка, самокат, броски. Керн против людей не используется.

**Заедание.** Хранить историю последних действий игрока. Если одна и та же связка повторяется, шкала растёт, разнообразие её снижает. Пороги:
- около 50%: враги ускоряются, начинаются «перескоки» кадра (короткий визуальный и звуковой глитч);
- 100%: последние 3 секунды ввода проигрываются заново без участия игрока.

Пока заедание высокое, шкала Аккорда не заряжается. Итоговое значение за главу сохраняется для расчёта концовки.

**Громкость.** Скрытый параметр Отпечатка. Огонь, взрывы и серия попаданий без пауз повышают её, датчик Ники понижает. Громкость влияет на урон и скорость босса. Игроку показывается только дрожанием камеры, искажением звука и светом, без цифр.

**Аккорд (суперудар).** Шкала заряжается разнообразием приёмов и парированиями. Удар по области, ломает текущую фазу босса.

**Последняя нота (ультраудар).** Доступна, когда шкала полна и босс в последней фазе дошёл до момента обрыва. Кинематографичный удар, завершает бой и даёт «хвост». Если босса просто добить, хвоста нет, а запись перезапускается через 40 секунд.

**Боссы.** У каждого три фазы и цикл атак, повторяющийся по ритму (запись повторяется, ритм можно выучить). Звук атаки предупреждает в такт. Ника голосом подсказывает момент последней ноты.

**Состояние прохождения** (сохраняется в localStorage, чтение и запись в try/catch):
`tails[]`, `comfortLies` (сколько раз выбрано утешение вместо правды), `jamPerChapter[]`, `listenedToKhozyayka`, `vetrovAlive`, выборы по главам. Концовка считается одной чистой функцией по условиям из раздела «Четыре концовки» сценария. На неё обязательно нужны unit-тесты.

**Юмор-слой.** Пуши приложения доставки, реплики Вани, оценка клиента после босса («Дружинник, 1380 г. — без чаевых»). Не показывать их во время серьёзных кат-сцен.

## Звук и музыка

- Адаптивная музыка из слоёв: тихий эмбиент ночного города; ритм-слой боя; слой «записи», который громче при высокой громкости Отпечатка.
- Эффект заедания: повтор последнего фрагмента звука, как скачок иглы на пластинке.
- Ритм атак босса совпадает с ритмом музыки, чтобы парирование можно было выучить на слух.
- Сначала звук синтезируется кодом. Места под будущие файлы (`public/audio/`) оставить через единый реестр звуков.

## Графика

- Стилизованный low-poly. Ночь, фонари, туман, неоновые вывески, холодный свет у Отпечатков.
- Пока нет моделей, персонажи и окружение собираются из примитивов. Модели подключаются через единый загрузчик glTF, чтобы потом заменить заглушки без правки логики.
- Разрешены только ассеты с открытой лицензией (CC0 и аналоги). Лицензию каждого ассета записывать в `public/CREDITS.md`.

## Ограничения по содержанию

- Реальных исторических людей и реальных брендов (сервисов доставки, магазинов) в игре нет. Приложение доставки и стрим-платформа вымышленные.
- Не копировать персонажей, сюжетные ходы и визуальный стиль других игр.
- Реальные места (Тула, проспект Ленина, кремль) показываются стилизованно и узнаваемо, без претензии на точную копию.

## План пролога

Делать по шагам. После каждого шага: игра собирается, запускается в Chrome, изменения запушены.

1. **Каркас.** Vite + TS + Three.js + Rapier, игровой цикл, ввод, деплой на Pages. Пустая сцена с полом и камерой открывается по ссылке.
2. **Контроллер Лёвы.** Бег, камера от третьего лица, рывок, коллизии.
3. **Ночная Тула.** Отрезок проспекта Ленина и стена кремля из примитивов, освещение, туман.
4. **Самокат и погоня.** Обучение бегу и рывку.
5. **Драка с людьми.** Термосумка: удар и блок, простые враги-люди.
6. **Боевая база с керном.** Серия ударов, парирование, захват цели.
7. **Системы.** Заедание, громкость, шкала Аккорда, HUD.
8. **Босс Дружинник.** Три фазы, ритм атак, Последняя нота, хвост, повтор «где князь?» каждые 40 секунд.
9. **Диалоги и выбор** «доиграть или добить». Появление Ники, кассета деда.
10. **Звук и музыка.** Адаптивные слои, эффект заедания.
11. **Юмор-слой и финиш.** Пуши, Ваня, оценка клиента, сохранение, главное меню.
12. **Полировка.** Баланс, производительность, проверка в Chrome.

## Как работать в этом репозитории

- Владелец проекта не программист: объясняй изменения простыми словами и коротко.
- Проверять игровые ощущения (удобство боя, сложность) может только владелец. После каждого шага пиши, что именно попробовать в игре.
- Если решение меняет сценарий или механику из `docs/scenario.md`, сначала спроси.
